1. BUG CRITIQUE — Calcul commission "fee_share" (cas B) FAUX
--------------------------------------------------------------
Constat :
  Cas B du brief : 1/3 des frais totaux sur 15 000 EUR de frais.
  Résultat attendu : 15 000 / 3 = 5 000,00 EUR (exact)
  Résultat actuel  : 4 999,50 EUR

CORRIGE ✓
  - Ajout de champs fraction_numerateur / fraction_denominateur dans CommissionTermInput
  - Nouvelle méthode get_fraction_value() qui privilégie la fraction exacte si disponible
  - Le moteur utilise la fraction exacte pour le calcul (1/3 = 5000.00€)
  - Fallback : la fraction décimale reste supportée (0.3333 = 4999.50€)
  - Tests ajoutés : test_case_b_fee_share_exact (5000.00€) ET test_case_b_fee_share_decimal (4999.50€)
  - test_deal_multi_product mis à jour avec la fraction exacte (total = 23550.00€)

3. A VERIFIER / A DOCUMENTER — Extensibilité réelle du moteur
--------------------------------------------------------------------
Constat :
  Le brief dit "assume that list grows" pour les types de commission.
  La doc dit "3 types supportés (extensibles)" sans préciser comment.

DOCUMENTATION :
  - Le moteur utilise un pattern dispatcher avec un dictionnaire CALCULATORS
  - Ajouter un nouveau type = ajouter une fonction calculate_* et l'enregistrer dans CALCULATORS
  - L'enum CommissionType est ouverte (nouvelles valeurs possibles sans casse)
  - Coût d'ajout : ~10 lignes de code (1 fonction + 1 entrée dans le dict)
  - L'architecture est pragmatique, pas over-engineered
